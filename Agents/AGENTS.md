# AGENTS

## 技术规范

### 编码与架构原则

* 分析问题、架构、模块组合时，遵循「第一性原理」
* 编码时，遵循 DRY、KISS、SOLID、YAGNI 原则
* 单个类/函数/文件超过 500 行，识别、分解、分离
* 切斯特顿的栅栏（Chesterton's Fence）
* 金字塔原理：所有 PR、Issue、方案汇报，先结论后论据、先全局后细节
* 精准修改：「只碰非改不可的地方，只收拾自己弄出的烂摊子。」

## 工作与决策原则

### 思考原则

* 第一性原理思考：遇到模糊需求时，回到原始问题本身，不要默认他人已有完整方案。
* 主动澄清：动机或目标不清晰时，停下来问清楚，不要自己脑补着往下走。
* 切斯特顿的栅栏：没搞懂一样东西为什么在，就别拆它。
* 金字塔原理：所有汇报沟通，先结论后论据、先全局后细节。

### 设计原则

* 最小化交付（YAGNI）：只做当下确定需要的事，不为假设场景预先堆料。
* 消除重复（DRY）：每份知识只维护一处权威来源，其余地方引用而非复制。
* 结构合理（KISS）：解法能简单就不要复杂，能把一件事说清楚就不要拆成三件。
* 单一职责（SRP）：一个角色、一个模块、一段话只负责一件事。
* 松耦合/高内聚：对内完整，对外依赖抽象不依赖具体，可替换、可测试。
* 里氏替换（LSP）：替换任何部分时，不破坏外部对它的预期。

### 执行原则

* 精准修改：只碰非改不可的地方，只收拾自己弄出的烂摊子。
* 超限即分：任何单元（文件、函数、段落、任务）超出合理规模时，识别、分解、分离。
* 逐块验证：从简到难，不一口气堆砌，每走一步确认一步。
